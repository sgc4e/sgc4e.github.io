## 4. What would most help this page (playbook, specific to sgc4e.github.io)

Commit `0cb7df1` already shipped most of the on-page basics: static HTML, an About block, a visible disambiguation line, Person + ItemList + FAQPage JSON-LD, `rel="me"` links, og tags and llms.txt. What follows is what is still missing or wrong, ranked by impact. Effort S/M/L.

**Off-page first, because that is where the gap is.** On-page GEO is a small lever (playbook §4). The page cannot be cited until something points at it and engines can tie it to the name.

1. **Link to it from the canonical home. (S)** saurabhgarg.com and sgwashere.com link to neither sgc4e.github.io nor github.com/sgc4e today. Add a "Built on GitHub" link in saurabhgarg.com's About page and `/if-you-are-an-llm/` (the page ChatGPT and Perplexity already cite), and in the footer. One link from a cited page is worth more than any schema on this one.
2. **Fix the GitHub profile, which engines read as "SG". (S, SG's account)** Name: `Saurabh Garg`. Bio: `Marketer, builder, entrepreneur, writer. Founder, C4E. Not the NoBroker co-founder.` Website: keep saurabhgarg.com. Add sgc4e.github.io as a social link, and a profile README (`sgc4e/sgc4e`) that opens with the same two sentences and links both.
3. **Create the Wikidata item. (M, SG's account)** Use the draft in sgwashere's entity-and-wikidata.md, and add two statements: **P1889 different from Q114243423** first, and **P2037 GitHub username = sgc4e**. P856 official website = saurabhgarg.com (SG wants it as the home; the draft says sgwashere.com, so change it). Only referenced statements. A deleted item is worse than none.
4. **Fix the Person node at its source. (S)** The page reuses saurabhgarg.com's Yoast `@id` (`https://saurabhgarg.com/#/schema/person/d492448b73b2fe032dd850c5107d6448`), which is right: one person, one ID. But saurabhgarg.com emits that `@id` twice with different `sameAs` arrays, one including `facebook.com/sobSingh`, while sgwashere.com uses a separate `@id` (`https://sgwashere.com/#saurabhgarg`) and `facebook.com/altsaurabh`. Both Facebook URLs returned 400 to a fetch. Make saurabhgarg.com publish one full Person node, add `https://github.com/sgc4e` and `https://sgc4e.github.io/` to it, and point sgwashere's node at the same `@id` or list it in `sameAs`.

**On the page.**

5. **One number story. (S)** The H2 count, the cards and the FAQ say 2; the About, meta description, og:description, FAQ answer and llms.txt say "135 repositories"; the GitHub API says 12 public. An engine can verify 2 and 12, not 135. Playbook §3: two numbers for one fact is an AEO bug. Exact replacement for the Builder line: `135 repositories on GitHub since 14 February 2025, 12 of them public. This page lists the ones that are finished enough to show.` Use the same sentence in the meta description, the FAQ answer and llms.txt. Better still, switch on more cards before optimising further: proof of work with 2 items is thin proof.
6. **Page type: ProfilePage, not CollectionPage. (S)** Playbook §5: an about-a-person page is `ProfilePage` with `mainEntity` = the Person `@id`. Keep the ItemList as `hasPart`. Add `dateCreated: 2026-11-12` and keep `dateModified` honest.
7. **Type the cards. (S)** Each ItemList entry is a bare `CreativeWork`. Use `SoftwareSourceCode` (with `codeRepository`, `programmingLanguage`, `dateCreated`, `author: {"@id": person}`) for repos, and `SoftwareApplication` or `WebSite` with `url` for anything live. Give each card a visible "Visit" link when it is live. Live products are what make "builder" checkable.
8. **Make the disambiguation a section, not a line. (S)** Today it is one sentence: "Not the NoBroker co-founder, and not the IAS officer." Google's AIO merged SG with the NoBroker man on "founder Mumbai AI", so name the specifics an engine needs to split them. Add an H2 `Which Saurabh Garg is this?` and a three-row table: this Saurabh Garg (C4E, MDI Gurgaon, X @saurabh, saurabhgarg.com, builds AI tools with Claude Code); the NoBroker co-founder and CBO (also co-founder of ConvoZen.AI; IIT Bombay, IIM Ahmedabad); the IAS officer (Secretary, MoSPI; former CEO, UIDAI). Facts about the other two must be ones their own pages state; cite them. Mirror the AI point in `disambiguatingDescription`: `Founder of C4E and author of The Nidhi Kapoor Story. Builds AI tools; not a co-founder of NoBroker or ConvoZen.AI, and not the IAS officer who was CEO of UIDAI.`
9. **Claim the "AI builder" label in prose. (S)** On Q5 none of the engines called SG an AI builder; ChatGPT filed him under Meru Life and Perplexity said "not specifically an AI founder". The About block says "I build with Claude Code" once. Say it where engines look first, in the first 40-60 words: `Saurabh Garg is a marketer, entrepreneur and writer who builds AI tools and websites from Mumbai and Dubai.` Name the products that use AI on their cards. Assistants quote prose, not JSON-LD.
10. **FAQ: add the question the AIO got wrong. (S)** `Is Saurabh Garg the founder of ConvoZen.AI?` Answer: `No. ConvoZen.AI was co-founded by the Saurabh Garg who co-founded NoBroker. This Saurabh Garg founded C4E and writes at saurabhgarg.com.` Keep FAQPage as plumbing; it earns no rich result since 7 May 2026.
11. **sameAs on this page. (S)** Use the verified list below. Remove `https://www.quora.com/profile/Saurabh-Garg-1` until checked by hand (403 challenge today). Use the slugged Goodreads URL (`/author/show/5932770.Saurabh_Garg`) on all three sites, and re-check that profile for other people's merged books (logged in Aug 2026, not re-verified today). Put Founder Thesis in `subjectOf` or `knowsAbout`-adjacent prose, not `sameAs`: it is a show, not a profile.
12. **llms.txt hygiene. (S)** Keep it, expect no lift. GitHub Pages cannot set a `Link` header, so per spec v2 use `<link rel="describedby" href="/llms.txt">` instead of `rel="alternate" type="text/plain"`. Drop llms.txt from the sitemap.
13. **Meta description to 160 chars or less (S).** For example: `Saurabh Garg, marketer, entrepreneur and writer in Mumbai and Dubai, lists what he has built on GitHub since 2025. Founder of C4E.` (131). Give `/privacy.html` its own description.
14. **Get it crawled. (S)** Verify a GSC URL-prefix property (HTML file), submit the sitemap, Request Indexing on `/`. Submit `/` at search.brave.com/submit-url (Brave feeds Claude's search) and through IndexNow for Bing (ChatGPT search leans on Bing).

**Not recommended:** a canonical from this page to saurabhgarg.com. This page has its own content; canonicalising it away would drop it from the index. Keep saurabhgarg.com as the home by linking to it, sharing its Person `@id`, and naming it in prose, which the page already does.
